# Product decision and opportunity sizing

## Proposed action

Prototype a concise suitability summary inside existing discovery, then validate comprehension and unmet need with makers before running a bounded experiment. New-to-craft discovery users are the proposed research focus. That focus comes from the working product hypothesis, not a measured Ravelry segment treatment effect. Review existing Ravelry functionality before deciding that an additional summary is needed.

## Sizing assumptions

The planning base is the fixed synthetic new-to-craft discovery cohort with complete 14-day follow-up. It is not future traffic or all Ravelry users. The app varies enrolled/reached eligible-account coverage (50%, 75%, 100%) and assumed absolute lift (+0.5, +1.0, +1.5, +2.0 percentage points).

Expected additional recorded starts = eligible accounts × coverage × absolute lift.

These are twelve deterministic sensitivity scenarios, not forecasts or confidence intervals. The example assumes the lift applies to the covered eligible population and no feedback/interference changes that effect. Coverage is not a post-assignment exposed-user filter. No revenue, true making, segment treatment heterogeneity or rollout equilibrium is inferred. Rounded counts are approximate expected values rather than observed people.

## Decision criteria

For a real test, agree the smallest useful lift and harm margins before observing outcomes, using actual baseline data and product costs. The current demo's primary/abandonment criteria remain unchanged: start lower 95% bound above zero, point estimate at least +1 point, abandonment upper bound below +1 point, valid allocation and mature follow-up.

The added attention sensitivity has its own fixed +3-point harm margin and account-cluster bootstrap. A numerical pass requires the upper interval for increased top-decile impression share below the margin. The stress scenario can therefore put an otherwise positive primary outcome on hold. This is an added review, not a retroactive claim about the original primary protocol.

Even all numerical checks passing is insufficient for actual rollout: maker experience, real instrumentation, current product research, designer feedback and interference assessment remain necessary. The app's recommendation stays at prototype/research/test; it does not conclude the feature works on Ravelry.
